# 08 — Implementation Phases

## Phase 0 — Freeze the contract

Deliverables:
- PRD
- claims policy
- source list
- data schemas
- one demo scenario
- architecture diagram
- score model draft
- kill list

Exit gate:
No agent may add scope without updating the PRD.

---

## Phase 1 — Prove YouCam live before UI polish

Build:
- server-side API client
- upload flow
- Skin Analysis task flow
- Makeup VTO task flow
- poller
- error normalization
- live smoke scripts
- response fixture recorder

Do not build a full frontend first.

Exit gate:
You possess at least one verified Skin Analysis fixture and one verified Makeup VTO result generated by real provider calls.

---

## Phase 2 — Canonical domain models

Build:
- SkinState schema
- ProductEvidence schema
- UserConstraints schema
- Decision schema
- DecisionReceipt schema
- provider normalization

Exit gate:
UI can be developed against these contracts without seeing raw provider JSON.

---

## Phase 3 — Decision engine

Build:
- hard eligibility
- soft scoring
- missing-evidence penalties
- confidence
- abstention
- reason codes
- counterfactual explanation
- canonical hash

Tests first.

Exit gate:
100% of rule paths covered and property tests green.

---

## Phase 4 — Curated product evidence

Build a small high-quality catalog.

For every product:
- sourced finish
- sourced coverage
- sourced claims
- ingredients if available
- VTO mapping
- provenance metadata

Exit gate:
demo products have no critical unknowns except those intentionally used to demonstrate uncertainty.

---

## Phase 5 — Core UX

Implement:
- landing
- moment
- selfie
- current signals
- compare
- decision
- VTO
- receipt
- privacy

Exit gate:
complete flow works with replay fixtures on mobile.

---

## Phase 6 — Live integration wiring

Switch replay provider adapter to live adapter behind same interface.

Exit gate:
same UI and same decision engine work in live mode.

---

## Phase 7 — Judge Mode

Create:
- deterministic scenario
- cached real provider artifacts
- replay badge
- API trace panel
- 60-second flow
- rubric proof labels

Exit gate:
10 consecutive Judge Mode runs without failure.

---

## Phase 8 — Reliability and security

Add:
- input limits
- MIME validation
- rate limiting
- CSRF/session considerations as relevant
- secret checks
- dependency audits
- image deletion/TTL
- error boundaries
- provider timeout
- circuit breaker if useful
- logs without PII

Exit gate:
security/audit checklist green.

---

## Phase 9 — Judge evidence

Generate:
- architecture diagram
- data flow diagram
- decision receipt example
- live vs replay explanation
- test summary
- performance/API-unit table
- known limitations
- claim ledger

Exit gate:
a skeptical engineer can audit the project without asking you what is real.

---

## Phase 10 — Submission collateral

Produce:
- README
- Devpost text
- screenshots
- 1–3 minute video
- setup instructions
- test instructions
- product tagline
- architecture diagram
- exit-interview answers

Exit gate:
submission mirrors actual code exactly.

---

# Branch strategy for AI agents

Recommended:

```text
main
feature/provider-youcam
feature/domain-contracts
feature/decision-engine
feature/product-evidence
feature/core-ux
feature/judge-mode
feature/audit-hardening
feature/submission
```

One canonical owner merges.

Agents do not independently change shared schemas.

Schema changes require:
1. explicit diff
2. test update
3. dependent package update
4. merge before parallel continuation
